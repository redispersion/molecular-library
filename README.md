# Общая библиотека молекулярных моделей

Локальное хранилище для разных проектов: молекула → конкретная модель → версия.
Создано 2026-11-13. Исходные проекты при импорте не менялись.

## Где что находится

- `molecules/<id>/molecule.json` — химическая идентичность. У неразобранных
  полимерных фрагментов и комплексов она явно предварительная.
- `molecules/<id>/models/<model>/v1/` — неизменённые ITP и согласованные по
  именам/порядку координаты, `model.json` с источниками, SHA256 и проверками.
- `molecules/<id>/structures/` — самостоятельные исходные и производные
  геометрии. Наличие структуры не означает наличие параметров для неё.
- `forcefields/` — архивные комплекты базовых FF, включая вспомогательные
  RTP/HDB/ATP и другие файлы. Версия источника может быть неизвестна.
- `incoming/` — неразобранные материалы, пока не рекомендованные к применению.
- `quarantine/` — отдельные исходные структуры, не прошедшие проверку формата.
- `catalog/` — инвентаризация, дубли, происхождение, каталог моделей и отчёт.
- `objects/sha256/` — единственное место хранения байтов файлов. Именованные
  файлы выше — относительные символические ссылки внутрь этой библиотеки.
  Они работают после переноса всей библиотеки. На исходные проекты ссылок нет.

Байтовые дубли хранятся один раз. Различные конформеры и различные параметры
не объединяются по одному лишь названию молекулы. JSON выбран для метаданных,
чтобы читать и проверять их стандартным Python без дополнительных зависимостей.

## Использование

Из корня библиотеки:

```bash
python3 tools/library.py list
python3 tools/library.py verify
python3 tools/library.py export molecules/5cb/models/gromos54a7-atb-569019/v1 /путь/к/проекту/inputs/5cb-atb-569019-v1
```

Экспорт создаёт обычные файлы и `model-selection.json` с точными контрольными
суммами. Существующий каталог не перезаписывается. Это снимок модели, не
собранная система: общий force field подключается и проверяется отдельно.
В `systems/` и `calc/` своего проекта создавайте боксы, топологии систем,
минимизацию, траектории и результаты. В библиотеку они не переносятся.

## Правила добавления и изменения

1. Сначала `incoming/` или отдельная новая модель; сохранить источник,
   дату, идентификатор записи, базовую версию FF и SHA256.
2. Хранить PDB/GRO, соответствующий конкретному ITP, рядом с ним. Проверять
   число, имена и порядок атомов. Для условных ITP требуется preprocessing.
3. Исходные загруженные файлы не редактировать. Исправление — новая версия
   `v2`, с описанием различий. Старые проекты остаются на прежней версии.
4. Физическую валидацию записывать с условиями и проверенными свойствами.
   Сейчас ни одна импортированная модель не объявлена физически валидированной.
5. Не менять объекты в `objects/` вручную: на один объект могут ссылаться
   несколько записей. Проверка `verify` обнаруживает повреждения.
6. До удаления старых копий в проектах отдельно мигрировать зависимости.
   При первоначальном импорте ничего не удалялось и не перенастраивалось.

Библиотека — локальный Git-репозиторий; удалённый сервер не настроен.
Публично публиковать скачанные FF следует только с учётом лицензий источников.
Для резервного копирования переносите весь каталог, сохраняя ссылки, либо
делайте архив `tar`, не разыменовывая их. Облачная копия пока не создана.
Первый Git-коммит пользователь может сделать после просмотра каталога.

## Ограничения импорта

Список проверенных корней и исключений — `catalog/scan.json`.
Просканированы научные/проектные каталоги и Downloads/Documents; это не
исчерпывающий поиск по всем дискам. Содержимое архивов и облака не проверялось.
Файлы программных дистрибутивов и учебные примеры только проиндексированы.
Собранные системы и результаты прогонов остаются в исходных проектах.

Разбор координат проверяет формат/число атомов, но не полную химическую
корректность. Некоторые диагностические файлы содержат NaN/Inf или имеют
нестандартный формат; отказ простого парсера не всегда означает повреждение.
Идентичность части записей определена по именам источников и требует проверки.
Старые черновики комплексов Chl a с ацетонитрилом не становятся утверждёнными
входами из-за импорта в библиотеку.

Главные текущие ограничения перечислены в `catalog/REPORT.md`.
